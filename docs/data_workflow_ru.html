1. Цель данных

Проект должен стать визуальным fashion-discovery сайтом для Литвы: пользователь ищет не по одному магазину, а по настроению, категории, цвету, размеру, цене и бренду, затем переходит на официальный сайт магазина через approved affiliate link.

1. Feed-ready Показать, что approved product feeds можно безопасно импортировать.
2. Единый каталог Привести разные фиды магазинов к одной модели товара.
3. Поиск и discovery Дать пользователю удобный поиск по vibe, категории, цвету и цене.
4. Деньги и атрибуция Связать outbound clicks с affiliate reports и комиссией.
MVP не является маркетплейсом, скрапером, checkout-системой или coupon сайтом. Покупка всегда происходит на стороне официального магазина.

2. Принципы работы с данными

Что делаем
  • Используем только approved affiliate feeds или written permission.
  • Храним raw rows для аудита и отладки.
  • Нормализуем товары в общую модель.
  • Делаем импорт идемпотентным.
  • Кешируем публичные страницы перед ростом трафика.
  • Храним affiliate subid без PII.
Чего избегаем
  • Не скрапим сайты магазинов.
  • Не показываем store как live без feed permission.
  • Не храним raw IP.
  • Не логиним каждого посетителя автоматически.
  • Не проксируем все merchant images через себя.
  • Не помечаем товары out of stock после failed import.

3. Общая архитектура данных

Affiliate networks VIVnetworks / CJ, Awin, direct partners

5. Workflow магазинов

Магазин нельзя сразу показывать как live source. Сначала нужно подтвердить affiliate access, правила, feed availability и возможность использовать images/deeplinks.

Research Находим affiliate network и feed signal
Tracker Заполняем store_tracker.csv
Apply Подаемся в affiliate program
Rules Сохраняем финальные условия
Feed config Создаем конфиг импорта
Live Показываем после успешного импорта
Статус Что означает Можно ли показывать товары
target Магазин интересен, но permission ещё нет. Нет
applied Заявка отправлена, ждём ответ. Нет
approved_deeplink Есть deeplink/click permission, feed может быть не готов. Ограниченно
approved_feed Есть разрешение и доступ к product feed. Да, после импорта
paused / blocked Правила, ошибки или операционная пауза. Нет

6. Feed config

Feed config описывает, как импортировать конкретный approved feed. В репозиторий можно класть только не-секретные настройки. URL с ключами, токены и пароли должны жить в environment secrets.

Поле Пример Комментарий
store_slug reserved_lt Связь с stores.slug.
source_type affiliate_feed Не scraper.
source_format xml XML, CSV, TSV или JSON.
is_full_snapshot true Определяет, можно ли ставить missing products в out of stock.
category_map reserved_v1 Версия внутренних правил нормализации категорий.
schedule daily Hourly только когда появится реальная необходимость.

7. Workflow импорта фида

1. Load rules Проверить store и program rules
2. Create run feed_import_runs.started
3. Download Скачать XML/CSV/JSON
4. Parse Разобрать строки
5. Normalize Категория, цена, цвет, размер
6. Upsert Raw rows, products, variants
  1. Загрузить store и affiliate rules.
  2. Остановить job, если feed permission не подтверждён.
  3. Создать feed_import_runs со статусом started.
  4. Скачать feed во временное хранилище.
  5. Посчитать hash фида и при полном совпадении завершить без лишней работы.
  6. Распарсить rows строго по формату.
  7. Проверить обязательные поля.
  8. Нормализовать canonical fields.
  9. Посчитать raw_hash и content_hash.
  10. Сохранить raw_feed_items.
  11. Upsert products по store_id + external_product_id.
  12. Upsert product_variants, если есть размеры/варианты.
  13. После full snapshot отметить unseen products как out_of_stock.
  14. Поставить changed products в очередь search reindex/enrichment.
  15. Завершить import run с counts, warnings и errors.
Важное правило: failed import не имеет права менять активные товары на out of stock. Иначе один сломанный feed может выключить весь магазин.

8. Нормализация товара

Фиды разных магазинов будут отличаться: названия полей, категории, цвета, размеры, цены, availability. Наша задача — сохранить source payload и одновременно собрать единый catalog model.

Source concept Canonical field Зачем
Merchant product ID external_product_id Уникальность товара внутри магазина.
Product name title Карточка и поиск.
Category path merchant_category, normalized_category Debug + фильтры/SEO.
Audience / department gender WOMAN / MAN / KIDS.
Color color_label, normalized_color Показ source color и общий color filter.
Price price, sale_price, old_price Карточка, sale, сортировка.
Product / affiliate URL product_url, affiliate_url Clickout и attribution.
Stock availability, in_stock, status Не показывать dead products.

Примеры нормализации

Raw input Normalized output
Women > Shoes > Trainers gender = woman, category = sneakers
Black / Noir / Juoda normalized_color = black
EU 42 normalized_size = eu_42
Out of stock in_stock = false, status = out_of_stock

9. Lifecycle товара

demo Синтетический товар до approval
active Товар из approved feed
out_of_stock Нет в наличии или исчез из full snapshot
removed Старый товар после retention window
blocked Скрыт оператором или validation rule
reactivated Вернулся в feed и снова active
Статус Показывать в поиске? Комментарий
demo Только в demo mode Нельзя выдавать за live merchant product.
active Да Основной публичный статус.
out_of_stock По умолчанию нет Можно хранить для истории.
removed Нет Старый товар, убран из public catalog.
blocked Нет Правила, legal issue или bad data.

10. Search workflow

User query Запрос, department, filters
Normalize trim, lowercase, filters JSON
Query catalog Postgres products или search index
Result count Считаем количество результатов
search_events Пишем событие
Product grid Возвращаем карточки

MVP search

  • Только active товары.
  • Фильтры: store, category, color, gender, price, availability.
  • Text search по title, brand, category, tags.
  • Search event создается после получения result count.
  • Популярные collection pages можно кешировать.

Когда нужен Meilisearch / Typesense

  • 100k+ active products.
  • Postgres facets стали медленными.
  • Нужны typo tolerance, synonyms и autocomplete.
  • Нужно лучше ранжировать vibe/style search.
Algolia лучше не включать рано: она удобная, но autocomplete и поисковые запросы могут быстро стать самой дорогой статьей.

12. Clickout workflow

Click User нажимает View in store
Load data Product, store, rules
Validate Status, host, affiliate permission
Create click outbound_clicks.pending
SubID fa_<short_click_id>
302 redirect В merchant / network URL

Destination priority

  1. Variant-level affiliate_url.
  2. Product-level affiliate_url.
  3. Approved deeplink template + product_url.
  4. product_url only if direct tracking is explicitly allowed.

Validation rules

  • Product exists and status is active.
  • Store is live.
  • Affiliate/deeplink rules allow clickout.
  • URL uses HTTPS.
  • Destination host is allowlisted.
  • Destination is not cart, checkout, admin or unknown host.

13. Affiliate reconciliation

Affiliate network reports обычно приходят с задержкой. На MVP можно делать reconciliation вручную, позже добавить таблицы для report import.

  1. Экспортировать report из affiliate network.
  2. Получить date range, store, click/subid, order status, commission.
  3. Сматчить report subid с outbound_clicks.affiliate_subid.
  4. Посчитать EPC, conversion rate, approval rate.
  5. Сравнить эффективность store/category/query.
Метрика Формула
Clicks count of outbound_clicks
Conversion rate approved orders / clicks
EPC commission / clicks
Approval rate approved orders / tracked orders
Revenue per session commission / sessions

15. Ошибки и алерты

Зона Что отслеживать Порог
Feed import Download failed, parse failed, zero valid products. Алерт сразу.
Feed quality Invalid rows, missing images, price parse errors. Invalid > 30%, missing image > 10%, price error > 2%.
Search Zero-result spike, slow response, index unavailable. По baseline после первых данных.
Clickout Blocked/failed redirects, unknown host. Failed clickout > 1%.
Privacy/security Raw IP in logs, PII in affiliate URL, credentials in logs. Алерт сразу.

20. Acceptance checklist

  • Ни один unapproved store не показан как live source.
  • Минимум один approved feed успешно импортируется.
  • Повторный импорт того же feed не создает дубли.
  • Failed import не делает active products out of stock.
  • Product cards показывают только valid public fields.
  • Search возвращает только active products.
  • Search event содержит query, filters и result count.
  • Clickout создает outbound_clicks до redirect.
  • Destination URL валидируется.
  • Affiliate subid не содержит PII.
  • Ошибки feed import видны оператору.
  • Legal/data source pages объясняют affiliate data usage.
  • Можно понять, какой store/query/category генерит clicks.
