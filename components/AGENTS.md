# components

## Purpose
Shared, route-agnostic React components for the Weft demo storefront: page chrome (header/footer), the product results grid, informational-page scaffolding, an account preferences panel, a browser-only "AI fitting room" mockup, a cinematic homepage hero, a decorative loading mascot with global search-transition state, and two fire-and-forget analytics beacon components. All are demo-safe — no real retailer data, no checkout, no external redirects — and all EN/LT copy is sourced from `lib/i18n.ts` rather than hardcoded ad hoc, with the exception of a handful of components that inline bilingual ternaries (`locale === "lt" ? … : …`) directly rather than going through the `copy` object.

## Key Files

|------|-------------|
| `account-dashboard.tsx` | `"use client"`. `AccountDashboard({ locale })`. Self-contained profile/preferences form (name, email, style chips, sizes, budget, sale/price alert toggles) persisted to `window.localStorage` under key `weft-account-preferences`; no server calls. Renders "Saved items" / "Recent searches" link cards that point at `/search` (not wired to real data). Ships its own scoped `<style>` block (`accountStyles`) rather than relying only on `globals.css`. Bilingual strings are inlined via `isLt` ternaries, not `lib/i18n.ts`. |

Lets the user pick a local photo (client-side `URL.createObjectURL`, validated to JPG/PNG/WEBP under 10MB, never uploaded anywhere) and select one product from a radio-group list, then shows a "Create try-on" button that only ever reaches a static "Generation is not connected yet" status — there is no real AI generation call. Uses `formatCategoryLabel` from `lib/i18n.ts` for the product category text and `next/image` for product thumbnails. Own scoped `<style>` block. |
| `cinematic-hero.tsx` | Server component (no `"use client"`). `CinematicHero({ locale })`. Uses `getCopy(locale).hero` and `withLocale` from `lib/i18n.ts`; some strings (headline, lead, quick-link labels) are inlined ternaries rather than `copy` entries. |
| `clickout-analytics-tracker.tsx` | `"use client"`. `ClickoutAnalyticsTracker({ productId })`. Renders nothing; on mount fires a `keepalive` `POST /api/analytics/click` with `{ placement: "product_grid", productId }` and silently swallows fetch errors so analytics never blocks the UI. |
| `filter-disclosure.tsx` | `"use client"`. `FilterDisclosure({ label, defaultOpen, children })`. A `<details>`/`<summary>` wrapper (class `advanced-filters`) used to collapse advanced search filters; tracks open state in React so it can be toggled, and closes + refocuses the summary on Escape for keyboard accessibility. No i18n of its own — `label` and `children` are passed in already localized by the caller. |
| `info-page.tsx` | Server component. Exports `InfoPage({ title, intro, children })` (page shell with `<h1>`/optional lead paragraph inside `.route-shell.info-route`) and `ProseSection({ title, children })` (a `.prose-section` block with optional `<h2>`). Pure layout primitives used by static content routes (about, terms, privacy, etc.); receives already-localized text as props. |
| `loading-mascot.tsx` | `"use client"`. The most complex file in the directory. Defines a global loading-indicator system built on React Context: `LoadingMascotProvider({ children, locale })` owns phase state (`idle` / `searching` / `found`), runs a hand-drawn SVG robot mascot (`MascotSvg`) animated with the Web Animations API (`element.animate`), respects `prefers-reduced-motion`, and uses a `MutationObserver` on `#main-content` plus min/max duration timers to decide when to end the "searching" phase. Also exports `MascotSearchForm` (a form wrapper that intercepts submit, builds a `/search?...` URL from `FormData`, calls the mascot controller's `start()`, and does a Next.js `router.push`/`router.refresh`), `SearchMascotSettler` (a bodyless component that calls `finish()` on mount/update — dropped onto the search results page so the mascot knows results arrived), and `RouteLoadingFallback({ label })` (a generic `aria-busy` loading shell for Suspense boundaries). |
| `product-grid.tsx` | Server component. `ProductGrid({ ariaLabel, locale, products })` where `products: MockProduct[]` from `lib/mock-products.ts`. Product links always point to `/out/{mock_product_id}` (the internal, non-redirecting demo click-out route) — this is the demo-data boundary in practice. Renders an empty-state message with a "clear filters" link when `products` is empty. |
| `search-analytics-tracker.tsx` | `"use client"`. `SearchAnalyticsTracker({ resultCount })`. Renders nothing; reads the current `useSearchParams()`, debounces 250ms, then fires a `keepalive` `POST /api/analytics/search` with an anonymous id (persisted in `localStorage` under `weft-anonymous-id`, falling back to an ephemeral id if storage is blocked), the query, a whitelisted subset of filter params (`availability|category|color|gender|sale|status|store`), sort, `resultCount`, and `sourcePage: "/search"`. Fetch errors are swallowed. |
| `site-footer.tsx` | `"use client"` (needs `useSearchParams` to detect `?lang=`). `SiteFooter()`. Renders brand link plus two nav columns (Discover / Information) built from `copy[locale].footer` in `lib/i18n.ts`, with two links (`/stores`, and one other) inlined rather than sourced from `copy`. All hrefs go through `withLocale`. |
| `site-header.tsx` | `"use client"`. `SiteHeader()`. Site-wide header: brand link, desktop nav (Search, Stores, AI fitting room, How it works, About — the latter two flagged `temporary: true` and styled/labelled accordingly), account link, a light/dark `ThemeToggle` (writes `document.documentElement.dataset.theme` + `localStorage.weft-theme`), an EN/LT language switcher that also sets a `weft-locale` cookie via `persistLocale`, and a `<details>`-based mobile menu duplicating the same nav. ## For AI Agents

### Working In This Directory
- **Copy source of truth**: prefer `lib/i18n.ts` (`copy`, `getCopy(locale)`, `formatCategoryLabel`, `formatColorLabel`, `formatGenderLabel`, `formatAvailabilityLabel`, `formatTagLabel`) over hardcoding strings. Several existing components (`account-dashboard.tsx`, `ai-fitting-room.tsx`, `cinematic-hero.tsx`, `site-footer.tsx`) already deviate from this by inlining `isLt`/`locale === "lt"` ternaries for some strings — treat that as existing debt, not a pattern to copy for new code; new copy should go into `lib/i18n.ts`'s `copy` object.
- **Client vs server**: `account-dashboard.tsx`, `ai-fitting-room.tsx`, `clickout-analytics-tracker.tsx`, `filter-disclosure.tsx`, `loading-mascot.tsx`, `search-analytics-tracker.tsx`, `site-footer.tsx`, and `site-header.tsx` are all `"use client"` (they use state, refs, browser storage, `useSearchParams`, or the WAAPI). `cinematic-hero.tsx`, `info-page.tsx`, and `product-grid.tsx` are plain server components — keep them that way; they take pre-resolved `locale`/data as props and do no client-only work.
- **Demo-data boundary**: product click-throughs must go through `/out/:mock_product_id` (see `product-grid.tsx`), never a direct external URL. Do not introduce real retailer names, logos, or checkout flows in these components.
- **Locale prop contract**: most components take `locale: Locale` (`"en" | "lt"`) as an explicit prop from the page/layout rather than resolving it themselves; `site-header.tsx` and `site-footer.tsx` are the exception — they derive locale internally from `useSearchParams()` + `getLocale`, since header/footer are typically rendered once per layout without a locale prop threaded through.
- **Analytics beacons are inert by design**: `clickout-analytics-tracker.tsx` and `search-analytics-tracker.tsx` render `null` and only exist for their `useEffect` side effect (`POST` to `/api/analytics/click` or `/api/analytics/search`, both `keepalive: true`, both swallow fetch failures). Never make these block rendering or throw — that's a deliberate pattern to keep telemetry non-critical.
- **No real AI backends**: `ai-fitting-room.tsx`'s "Create try-on" and the account dashboard's alert toggles are UI-only; there is no photo upload endpoint and no generation call. Don't assume server plumbing exists for these — if wiring them up for real, you're adding new API routes, not connecting to hidden ones.

### Common Patterns
- Components that need heavy bespoke CSS (not just utility classes from `globals.css`) ship a co-located template-literal `<style>` string at the bottom of the file (see `accountStyles` in `account-dashboard.tsx`, `fittingStyles` in `ai-fitting-room.tsx`) rather than a separate `.css`/CSS-module file.
- Price formatting is consistently `new Intl.NumberFormat(locale === "lt" ? "lt-LT" : "en-IE", { style: "currency", currency })` — duplicated in `product-grid.tsx` and `ai-fitting-room.tsx` rather than shared as a helper.
- Icons are from `lucide-react`, always rendered with `aria-hidden="true"` when decorative.
- Interactive/toggle UI favors native elements for accessibility and no-JS resilience: `<details>`/`<summary>` for `filter-disclosure.tsx` and the mobile nav in `site-header.tsx`; native `<input type="checkbox">`/`<select>` in `account-dashboard.tsx`.
- Components that fetch analytics or persist local state wrap browser API calls (`localStorage`, `fetch`) in `try/catch` or `.catch()` and degrade silently — privacy-restricted browsers or offline states must never break the page.
- `next/image` is used for known static/demo assets; raw `<img>` is used only for user-supplied blob URLs (`ai-fitting-room.tsx` photo preview) since `next/image` can't optimize `blob:` URLs.

## Dependencies

### Internal
- `lib/i18n.ts` — `Locale` type, `copy`, `getCopy`, `getLocale`, `withLocale`, `formatCategoryLabel`, `formatColorLabel`, `formatGenderLabel`, `formatAvailabilityLabel` (used across most components).
- `lib/mock-products.ts` — `MockProduct` type consumed by `product-grid.tsx`.
- `lib/demo-stores.ts` — `getPublicDemoStoreById`, `getPublicDemoStoreLabel` consumed by `product-grid.tsx`.
- `app/api/analytics/click/route.ts` and `app/api/analytics/search/route.ts` — endpoints called by `clickout-analytics-tracker.tsx` and `search-analytics-tracker.tsx` respectively.
- `app/globals.css` — supplies the CSS custom-property theme (`--color-ink`, `--color-accent`, `--color-surface`, etc.) that both `globals.css`-based classNames and the components' own inline `<style>` blocks style against.

### External
- `lucide-react` — icon set used throughout (Bell, Bookmark, Check, Search, Sparkles, Menu, Moon, Sun, UserRound, ArrowRight, Footprints, ImageOff, Shirt, ShoppingBag, SlidersHorizontal, etc.).
- `next/image`, `next/link`, `next/navigation` (`useRouter`, `usePathname`, `useSearchParams`) — Next.js App Router primitives.
- `react` — hooks (`useState`, `useEffect`, `useRef`, `useMemo`, `useCallback`, `useContext`, `createContext`) and the `SubmitEvent`/`ComponentPropsWithoutRef` types used in `loading-mascot.tsx`.
